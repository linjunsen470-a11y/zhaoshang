# Payload CMS 上手指南

更新：2026-10-16。

## 先认清四个入口

| 入口 | 用来做什么 |
| --- | --- |
| 运营工作台 | 从三个日常入口开始，优先处理提交较早的待联系咨询 |
| 项目与铺位 | 录入、修改和上下架；分享素材、上架检查在这里的工具区 |
| 咨询收件箱 | 查看客户需求、联系客户、改处理状态和写内部备注 |
| 系统设置 | 账号与媒体管理，仅管理员可见 |

## 录入并公开一条记录

1. 打开「项目与铺位 → 新建项目/铺位」。
2. 选录入对象：一间店或一个档口选「具体铺位」；整体招商、以后需要挂多个铺位的选「项目招商」。整项目只支持招商，转让选具体铺位。
3. 填「基本资料」。带 * 的内容保存时必填；公开前还须选择商业场景、至少有一张详情实景图。独立铺位的「所属项目」留空。
4. 在右侧选「公开状态」，再点页面保存按钮。资料检查只说明基本必填是否齐全；仍需核实图片可公开、费用与面积正确。

| 公开状态 | 客户能否在小程序看到 |
| --- | --- |
| 草稿、已下架 | 否 |
| 开放中、即将开放、已满/已转 | 是；已满/已转的记录不接受新咨询 |

所属项目不公开时，其铺位也暂停公开。项目已满不自动修改各铺位状态，请分别核实。学校名称只供后台管理，小程序统一脱敏为「城市 + 区域 + 某学校」。

「面积展示文字」「费用说明」是给客户看的文案；折叠的数值栏用于筛选。固定 50㎡填最小 50、最大 50；30–80㎡填 30 和 80；未知时两栏都留空。月租不含未注明的附加费用，年费和转让费写入费用说明，勿冒充月租。

已保存的项目招商记录可以通过「新增所属铺位」建立关联，无需输入项目 ID。商业场景、城市、区域必须与所属项目一致。

## 处理一条客户咨询

1. 在收件箱查看需求，普通跟进点「快速处理」；需要原始资料、附件或设备发布设置时点「查看详情」。
2. 电话联系后更新「咨询处理状态」，必要时补一条内部备注，再保存。
3. 详情页的「客户原文」记录首次提交，只读；需要修正联系方式和需求时使用「处理编辑」。右侧的处理状态和备注始终可见。

| 处理状态 | 唯一含义 |
| --- | --- |
| 待联系 | 尚未联系 |
| 已联系 | 已沟通，继续跟进 |
| 已结束 | 不再跟进；不代表已成交 |

设备的「发布状态」独立于咨询处理状态。要出现在小程序设备列表，进入「查看详情 → 处理编辑 → 设备公开设置」，确认内容后选「已发布」并保存。把咨询改成已联系或已结束都不会自动发布/下架设备。

转让咨询生成的是待完善的房源草稿，仍需补齐资料并上架；用户上传附件不能直接作为公开房源图片。

## 分享与检查

- 项目列表的「上架检查」用于查缺项；「必填已齐」不等同于已上架或已审核。
- 项目列表的「分享素材」展示最近更新的 20 条公开记录，生成分享文案、小程序码和海报；真实小程序码依赖微信配置。
- 常用列表只展示搜索、场景、区域；其余条件在「更多筛选与排序」。已设置的隐藏条件有提示，可点「清除全部筛选」复位。

移除首页漏斗/成交暗示和编辑页重复的保存发布按钮；折叠选填信息；隐藏无实际作用的完整学校名开关；统一前后端资料检查；将资料筛选改为先筛选、再计数和分页；移除四次无用的工作台统计查询及重复加载代码。

`pnpm backend:lint`、`pnpm backend:build` 和 43 项单元/规则测试通过（客户端 23、后端 16、CMS 4）；真实 HTTP 契约默认跳过。对比重排前后，项目 49、咨询 39 个存储字段的路径、类型、默认值、关系、选项值和约束保持一致，无需为本轮布局调整做数据迁移。

源码组件配隔离数据的首页预览已取得可访问性快照，导航和待联系列表正常渲染。截图接口随后无响应，后续列表视觉/交互验收未完成。本机 PostgreSQL/Docker 服务未运行，真实 Payload 登录、保存、数据库筛选与权限流程仍需在可用测试环境复验；本轮未连接业务库写入数据。
