# 前端业务范围与体验调整


## 页面调整

- 小程序首页改为「学校商铺」「园区与写字楼」纯文字双栏入口，底层仍保留三种实际场景；辅助操作收为「帮我找铺」「更多服务」，转让、设备、装修放入底部面板。推荐房源与最新房源去重。
- 找铺页显示「全部」「学校商铺」「园区与写字楼」；区域、月租、面积保留一级筛选，内容类型、经营品类等移至“更多”。合并类可在“更多”细筛工业园区或写字楼，旧精确场景链接仍有效。默认只展示开放中、即将开放，显示结果数，提供带当前场景的找铺需求入口。
- 收藏可以查看已租满房源，详情提供“找相似房源”。失效详情提供浏览房源和通用需求入口；网络异常保留重试。
- 内置旧业态演示缓存会清理，补充园区、写字楼演示样例。示意图片继续标注，避免当作真实项目摄影。
- 网页按三个场景分别获取最多四条可咨询房源，使用真实接口、图片和完整费用说明；空场景可直接登记相应需求。
- 网页“咨询这处房源”预选关联房源，锁定场景和咨询类型。提交时服务端核对房源公开状态，保存数字类型房源关联，原始咨询快照仍按既有规则生成。

## 后台与数据

- 房源和咨询的场景选项与数据库枚举均仅保留 `campus`、`industrial_park`、`office`。
- 删除 `communityInfo`、`tourismInfo`、`mallInfo` 字段和接口映射，移除校外临校类型。
- 已使用仓库指定的 `backend/scripts/push-schema.ts` 同步本机独立演示库 `zhaoshang_tencent_demo_20261024`。同步前备份位于 `scratch/backups/demo-before-scope-cleanup-20261025.dump`，未操作原项目数据库。
- 已核实旧字段数量为 0、场景枚举仅剩三项；正常启动仍为 `PAYLOAD_DB_PUSH=false`。

- `pnpm test:ci`：29 个客户端单元测试、25 个后台单元测试通过；隔离 HTTP 合同测试因未配置专用环境跳过。
- `pnpm --dir backend test:cms`：4 个测试通过。
- `pnpm backend:lint`、`pnpm backend:build`：通过。
- `node scripts/mp-check-templates.mjs`：全部 WXML、WXSS 编译通过。
- Chrome 实际验证桌面与 390px 手机布局、无横向溢出、仅三类场景、旧场景筛选返回 400、关联房源咨询真实写入后台、失效链接回退、场景预选表单。演示咨询称呼为“页面验收样例”，不是真实客户。
- 微信开发者工具实际读到三类首页入口、默认排除已租满的真实后台房源列表（2 条）。后续缓存切换、截图接口出现 RPC timeout；Windows 窗口捕获也失败，未将这部分完整 E2E 或小程序视觉检查记为通过。缓存清理、筛选回退、详情异常恢复等由单元测试覆盖。
