# 腾讯云迁移与域名切换规划

日期：2026-10-31。本文为部署前分析，不代表服务已迁移或通过上线验收。

后续进展：用户更正 SSH 用户后，已完成云端隔离测试部署，并确认改用新 AppID。实际状态以 [腾讯云测试部署记录](tencent-cloud-test-deployment-2026-10-31.md) 为准；下文保留部署前分析。

## 结论

可以将本机的 Next.js/Payload CMS、API、PostgreSQL、媒体文件及后续启用的腾讯文档同步进程迁往腾讯云。云端安装 Docker Engine/Compose，重新构建 Linux 镜像并恢复数据，不需要搬运整个 Windows Docker Desktop 环境。微信小程序客户端仍通过微信平台上传、审核和发布。

推荐先完成私有云端部署和测试，再直接使用自有域名 `api.jinyifangchan.com`。用户确认当前服务器为腾讯云，拟借用的 `cqwushi.com` 在阿里云接入、备案主体为另一家公司，已取得使用授权。因此，借用其子域名不是立即可用的无手续捷径。

## 已核实的项目状态

| 项目 | 当前状态 | 部署影响 |
| --- | --- | --- |
| 根目录 Compose | 仅有 `payload`，没有数据库或反向代理；映射 `3000:3000` | 需准备数据库、HTTPS 入口及端口隔离 |
| 根目录 `.env` | 有 SSH 信息和旧 `POSTGRES_*`，缺少当前 Compose 要求的 `DATABASE_URI` 及完整微信生产配置 | 不能直接作为生产配置运行 |
| 后端 `.env` | 数据库地址为本机 `localhost:5432`；`WECHAT_AUTH_MODE=dev` | 云端容器不能沿用 localhost 数据库地址，公网服务需真实微信鉴权 |
| 小程序环境 | develop 默认本地 mock；trial/release API 地址为空 | 云端联调须显式选择真实 API；正式接入需填写地址并发布代码 |
| 媒体 | `backend/media` 当前有 32 个文件，约 3.3 MiB | 数据库和媒体文件必须成套迁移；本次未核对数据库引用完整性 |
| 腾讯同步配置 | `backend/.tencent-sync/config.json` 存在，连接地址与令牌未配置，自动同步关闭 | 不能宣称当前同步已接通；迁移后先保持关闭 |
| 腾讯同步运行时 | 单独的 `scripts/sync-tencent.ts --watch`；状态目录默认为 `.tencent-sync` | 现有 Compose 未包含 worker 或该目录的持久化 |
| 生产镜像 | 启动 Next server；执行过 `pnpm prune --prod`，没有显式复制同步/建表脚本 | 需为同步和显式 schema 操作准备专用运行方式，不能直接假设镜像可执行这些命令 |
| SSH 检查 | 使用根目录 `.env` 的账号、端口及密码尝试连接，返回 `Authentication failed` | 未执行远程命令，CPU/内存/磁盘/系统/现有服务均未确认 |

本次本机 Docker 清单读取还受到 Docker Desktop 管道权限限制，因此未确认本机实际容器版本、卷映射和数据库大小。工作区有大量既有未提交修改；部署前应固定并验收明确的发布版本。

## 公网 IP 和借用域名的边界

公网 IP 可以用于 SSH 和受限的服务器测试。腾讯云文档区分未绑定域名的 IP 测试与正式提供互联网服务；不要把 IP 或更换端口当作上线备案的替代。推荐 CMS/API 只绑定服务器回环地址或 Docker 内部网络，通过 SSH 本地端口转发访问。正式微信网络请求要求 HTTPS 和已配置的服务器域名，公网 IP 不能作为本项目的正式服务器域名。[腾讯云备案场景说明](https://cloud.tencent.com/document/product/243/19630)、[微信网络文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。

如确需使用 `api.cqwushi.com`：

1. 由原备案公司配合，将 `cqwushi.com` 办理腾讯云新增接入。企业主域名已有备案不意味着子域名可直接跨接入商使用。可保留阿里云原接入，不需要迁移整个主站或域名注册商。[腾讯云接入备案](https://cloud.tencent.com/document/product/243/37403)。
2. 核对腾讯云账号实名、服务器备案资格和跨账号授权方式。接入备案不能把原备案主体直接改成本项目公司；域名使用授权也不等于服务器备案资源授权。[腾讯云备案 FAQ](https://cloud.tencent.com/document/faq/243/73180)。
3. 向腾讯云备案专员如实说明“另一家公司备案的子域名，用于广州锦奕咨询服务有限公司的小程序 API/CMS”，确认服务内容、责任主体和授权材料是否可接受，必要时办理变更。当前信息不足以认定这种安排必然允许或必然禁止；微信后台域名校验通过也不等于上述手续已完成。
4. 按腾讯云控制台对该订单的接入及访问放行要求完成操作，再配置子域名 A 记录和 HTTPS。部分接入场景初审后可放行，以实际订单为准，不把初审视为管局备案最终完成。
5. 在微信公众平台分别配置 request、uploadFile、downloadFile 实际使用的 HTTPS 原点；不是只填根域名，也不在服务器域名栏填 `/api`。当前项目以原生小程序 API 为主，不因使用 API 就额外配置 web-view 业务域名。

小程序自身的备案仍需完成，已有网站域名备案不能代替小程序备案。[工信部 APP 备案解读](https://www.miit.gov.cn/jgsj/xgj/hlwgl/art/2023/art_564bf0759d7e41d5b4aa8ce4996b9e84.html)。

## 建议的初期架构

```text
微信小程序 / CMS 浏览器
           |
     HTTPS 443 反向代理
           |
    Next.js + Payload
      |          |
 PostgreSQL   media 持久卷
      |
 腾讯文档同步 worker（后续授权验证后启用）
      |
 .tencent-sync 持久卷（与 CMS 共享）
```

可先在同一台服务器运行反向代理、应用和 PostgreSQL，符合项目初期分散访问的定位。若预算和运维需求允许，可将 PostgreSQL 改为同地域托管数据库。单机同盘有共同故障风险，数据库与媒体备份必须复制到服务器之外，并验证恢复。

容量仅作部署预算估计：2 核 4 GiB 可作为低流量试运行起点，4 核 8 GiB 更有余量；这不是压测结论，也不是立即升级建议。先确认已购机器配置、CPU 架构、可用磁盘、带宽和流量包。小内存机器优先在其他 Linux 构建环境构建匹配架构的镜像，再传到服务器运行，避免构建占满业务内存；同时验证镜像仓库与依赖源的实际可达性。

公网开放 HTTPS，HTTP 按证书验证/跳转需要开放；SSH 限制来源并逐步采用密钥。应用 3000 和数据库 5432 不直接开放公网。反向代理正确传递协议和主机，覆盖可信客户端 IP 头；结合现有 IP 限流测试，不盲目信任客户端自填转发头。上传请求大小、超时按当前接口限制配套设置。

`website/` 是独立静态公司官网，不在 CMS 镜像或当前 Compose 内。若也迁至腾讯云，可由反向代理静态托管；其自有域名完成接入前保留现有安排。

## 实施顺序及验收

1. **恢复只读盘点。** 在本地 `.env` 修正 SSH 信息或提供密钥路径，确认服务器系统、CPU 架构、容量、现有监听和运行服务。核验首次 SSH 主机指纹。先检查资源，不覆盖已有服务。
2. **固定发布版本并补齐部署文件。** 准备生产 Compose/反向代理配置、持久卷、健康检查、重启策略、日志轮转、独立 schema 执行方式，以及可选同步 worker。生成独立的生产密钥，不复用开发占位密钥。
3. **确定迁移数据范围。** 当前库为演示库；新生产库不应自动携带演示咨询、测试账号和开发 OpenID。测试环境可完整迁入现有演示数据，生产导入经确认的房源和媒体。若保留真实数据，停止同步及写入，执行完整逻辑备份与媒体备份，在云端独立数据库恢复并校验记录、关联及图片。不要直接跨版本复制 Postgres 数据目录。
4. **显式准备 Schema。** 已有数据先备份；在目标环境显式运行 `backend/scripts/push-schema.ts`，审查变更。日常启动和镜像构建保持 `PAYLOAD_DB_PUSH=false`。执行脚本时核对目标数据库，不让本地 env 覆盖目标连接。
5. **完成私有验收。** 经 SSH 隧道检查管理后台登录、房源列表/详情、权限隔离、咨询创建/编辑/删除及附件所有权。验证容器重建、服务器重启后数据库和图片仍在，以及备份能恢复。测试数据和真实业务隔离。
6. **接通正式域名与微信。** 优先自有 `api.jinyifangchan.com`，完成 DNS、证书、ICP备案接入、微信服务器域名和小程序备案。真实微信鉴权、手机号授权、上传/下载须在合法域名下通过真机验证，开发工具跳过校验不计为正式通过。
7. **验收同步后启用。** 配置腾讯文档无人值守连接，先做受控同步检查导入、导出、图片和错误报告，再运行 worker。持久化配置和状态，确保只有计划中的同步进程运行；不能让本机遗留进程继续写生产库。既有文档记录的腾讯视图筛选问题须单独验收，不能因迁移而认定解决。
8. **正式切换。** trial/release 写入已验收地址，上传体验版、验收并完成审核发布；确认云端是唯一业务写入源后，本机仅保留开发用途。生产验收需覆盖数据库、鉴权和权限的相应测试；本次规划未运行这些测试或生产构建。

生产关键配置包括：

```dotenv
NODE_ENV=production
PAYLOAD_PUBLIC_SERVER_URL=https://api.jinyifangchan.com
WECHAT_AUTH_MODE=wechat
WECHAT_CODE_ENV_VERSION=release
PAYLOAD_DB_PUSH=false
# 另外安全配置 DATABASE_URI、PAYLOAD_SECRET、MINIPROGRAM_TOKEN_SECRET、
# WECHAT_APPID、WECHAT_APP_SECRET；如需同步再配置对应连接与持久目录。
```

`PAYLOAD_PUBLIC_SERVER_URL` 不带 `/api`；小程序 API 地址为 `https://api.jinyifangchan.com/api`。具体值必须等目标域名验收后启用。数据库在同一 Compose 时使用实际数据库服务名，在外部数据库时使用其可达地址，不能沿用容器内 localhost。

## 若先借用域名，后续如何切换

技术上不需要为换域名再次迁数据库或搬服务器，两个域名可以临时指向同一套应用、数据库和媒体。

1. 新域名先完成备案接入、DNS 和 HTTPS；核对小程序备案中服务域名信息是否需同步变更。
2. 微信服务器域名先同时加入新旧原点，并覆盖上传、下载等实际请求；新域名可用后再让后端生成新媒体地址。
3. 更新后端 `PAYLOAD_PUBLIC_SERVER_URL`，核查历史绝对图片 URL、微信本地缓存及分享素材。本项目 `absoluteUrl()` 会原样保留已是 HTTP(S) 的地址，不能假设改一个环境变量就会重写所有旧链接。只处理实际发现的域名引用，不添加历史数据兼容层。
4. 修改 `mp/config/environments.js` 的 trial/release 地址，先体验版真机验收，再按微信流程审核发布。保持 AppID、数据库和正常使用的签名密钥稳定；域名变化本身不改变 OpenID，后台新域名登录需重新建立会话。
5. 在客户端更新过渡期继续让旧域名直接服务同一后端，不依赖 API 的跨域 301/302 跳转。观察旧域名流量、旧版本覆盖及图片引用后再退出旧入口；退出顺序为应用引用、微信域名配置和 DNS/证书，并与域名所有者协调相应接入管理。

如果尚未对用户发布，直接启用自有域名可省去这次客户端更新和旧入口维护。当前优先级是修复 SSH 认证、确认服务器资源并搭建私有测试环境，同时推进自有域名备案。
