# 首页与找铺分组改版

## 页面与交互

首页采用「学校商铺」「园区与写字楼」两栏，移除单字方块。下方为「帮我找铺」「更多服务」两项 28rpx 文字操作；更多服务以底部面板呈现委托转让、餐饮设备、商铺装修，支持遮罩、关闭及取消按钮，并为底部安全区留白。

找铺页使用两组浏览分类；园区、写字楼仍是实际 `businessScene`，可在更多筛选中细分。细筛只在确认后请求，取消丢弃修改，分组切换保留区域、面积、租金及关键词，清除不适用细类。旧 `businessScene=industrial_park|office` 链接恢复合并组与精确细筛。

进入找铺需求时，学校或明确物业类型预填原场景；未细分的合并组默认不限，并提示可以选择工业园区或写字楼。未修改咨询提交字段或数据库枚举。

## 查询接口

`GET /api/projects` 增加可选 `sceneGroup=campus|workplace`：前者匹配学校（含原校园类型的历史空场景数据），后者匹配工业园区和写字楼。未知组返回 400；与原 `businessScene` 同时传入时取交集。所有过滤均在分页和计数前执行。

共享浏览组定义由后台商业字典生成到小程序，Storage、根 Mock API、真实后台执行相同成员过滤。官网沿用原实际场景查询。

## 隔离验收环境

旧 `zhaoshang_commercial_test_20260922` 包含历史 CRM 结构，首次 HTTP 检查因枚举过时失败；未执行其 schema 更改。其备份为 `scratch/backups/isolated-before-scene-test-20261025.dump`。

新建专用 `zhaoshang_scene_group_test_20261025`，先备份至 `scratch/backups/scene-group-test-before-schema-20261025.dump`，再使用仓库指定 `scripts/push-schema.ts` 初始化。日常和测试服务均保持 `PAYLOAD_DB_PUSH=false`。

独立测试服务使用 `NEXT_DIST_DIR=.next-scene-test` 与 3100 端口，避免影响 3000 演示服务。运行服务和测试前设置 `COMMERCIAL_TEST_DATABASE=zhaoshang_scene_group_test_20261025`，通过 `tests/with-commercial-db.mjs` 传入隔离库。完整 HTTP 测试含混合三场景共 36 条临时房源，验证合并 24 条分两页、细筛各 12 条及原安全流程，并清理本次记录。
