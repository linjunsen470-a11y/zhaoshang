## 无镜像仓库方案的评估边界

本次没有实施取消 CCR。当前 Gitee 流水线只负责构建并推送到 CCR，缺少 SSH 部署阶段，因此镜像上传成功不等于 VPS 已更新。

使用 `docker image save` 导出、SSH 传输、`docker image load` 导入在技术上可行。单 VPS、低频发布时可少维护一个仓库账号；但仍需产物校验、失败重传、提交版本绑定、回退产物保留与空间清理。通常传完整镜像归档，而 registry 可以复用已有层。

Gitee 的现有 `image-build-plus` 插件是否能向后续任务暴露本地 Docker 镜像或归档，尚未实测；若不支持，需要改为能导出归档的构建任务。两端处于大陆只能降低跨境链路风险，不能证明带宽、传输限额、超时和稳定性必然满足要求。若最终选择直传，应先在隔离目录测试完整两份镜像的实际体积、导出/上传/导入耗时和中断恢复，再替换发布方案。
