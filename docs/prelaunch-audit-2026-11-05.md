**A1：原生接口能读到小程序接口已经隐藏的学校信息**

位置：[Projects.ts](../backend/collections/Projects.ts)、[学校字段](../backend/collections/Projects.ts)、[自定义脱敏出口](../backend/app/api/_shared/payloadApi.ts)。

匿名读取原生 `projects` 集合只受公开状态条件限制，学校名称、简称以及可能含校名的标题/地址没有统一脱敏。小程序自定义 API 的 `mapProject()` 才调用脱敏函数。

本次对当前开发 API 发出普通匿名 GET：同一校园项目在 `/api/projects?limit=1` 中学校名称为空，而 `/api/payload/projects?limit=1&depth=0` 返回 200 且学校名称非空。报告不记录具体学校名称。攻击者无需登录，也不必操作小程序界面。

最小修复是让原生 `projects` 的 `read` 仅允许工作人员，公众使用已有自定义接口；同步确认服务端 Local API 的调用不受误伤。仅隐藏一个 `schoolName` 字段不够，因为标题、地址和关联对象可能包含同一信息。验收应覆盖原生列表/详情/关联查询与自定义列表/详情，确认后台仍可编辑。

[公开搜索](../backend/lib/commercial.ts) 仍搜索真实学校名称。若业务要求学校身份不能被推断，应让公开搜索只搜索可公开内容；若只是避免页面直接展示，应明确这条边界。此项没有另计一个漏洞。

**A2：Next.js 已知拒绝服务风险适用于当前后台**

位置：[版本](../backend/package.json)、[后台 Server Action](../backend/app/admin/[[...segments]]/actions.ts)。当前为 `next 16.3.8`，后台使用 App Router 和 Server Action。

官方公告 GHSA-p3m5-59mp-jv5r 指出，该组合可能被特制请求消耗 CPU，使同一进程无法继续处理请求；本项目后台与小程序 API 共用进程，因此影响不只限于后台页面。公告修复版为 16.4.1；应选择与 Payload 兼容、覆盖该修复的版本，同时核对 `eslint-config-next` 与锁文件，再回归。没有对线上执行漏洞利用验证。[Vercel 官方公告](https://github.com/vercel/next.js/security/advisories/GHSA-p3m5-59mp-jv5r)

生产依赖审计共返回 23 条公告：3 critical、9 high、7 moderate、4 low，涉及 next、undici、dompurify、happy-dom、fast-uri、zod、deepmerge。这里的数量是依赖公告数量，**不等于 23 个已证实可利用漏洞**。

当前已确定适用的是上述 Server Actions DoS；其余要按实际执行路径复核。[现有 overrides](../backend/pnpm-workspace.yaml) 固定了部分较旧补丁版本，维护依赖时应一并检查，不能认为“已经有 override”就持续安全。

两个 critical 不宜直接报成已可利用 RCE：Image/SVG 公告给出的规避条件包含 `sharp >=0.35.5`，当前已符合；另一项需要相关 `use cache` 功能，仓库未发现该用法。[Image/SVG 公告](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw)、[use cache 公告](https://github.com/vercel/next.js/security/advisories/GHSA-673q-mjm6-r5xr)
