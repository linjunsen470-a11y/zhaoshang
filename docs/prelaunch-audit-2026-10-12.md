## 正式发布前仍需完成

当前静态闸门的九项：

1. 在 `mp/config/environments.js` 填写体验版 HTTPS API 地址。
2. 填写正式版 HTTPS API 地址。
3. 在 `mp/config/index.js` 填写真顾问电话。
4. 配置独立、至少 32 字符的随机 `MINIPROGRAM_TOKEN_SECRET`，与 `PAYLOAD_SECRET` 不同。
5. 设置 `WECHAT_AUTH_MODE=wechat`。
6. 在部署环境填写真实 `WECHAT_APP_SECRET`。
7. 统一后端 `WECHAT_APPID` 与小程序项目 appid。
8. 设置 `WECHAT_CODE_ENV_VERSION=release`。
9. 设置真实 HTTPS `PAYLOAD_PUBLIC_SERVER_URL`。

补齐配置后重新运行 `pnpm launch:check`。它只验证静态配置，还需在目标环境完成：HTTPS 和微信公众平台 request/uploadFile/downloadFile 合法域名、真实微信登录与双账号隔离、实际小程序码、隐私授权、真机图片展示与上传、实际运营内容和顾问电话。


当前 Compose 仅包含后端，连接由 `DATABASE_URI` 指向的 PostgreSQL。生产反向代理必须覆盖不可信的转发 IP 请求头。当前限流是单实例内存实现，多副本部署需要共享限流存储。

正式发布前还须完成目标数据库与 media 卷的配套备份/恢复演练。本地新增卷上传验证不等同于生产备份验证。未配置邮件适配器的环境不能视为密码找回投递已验收。
