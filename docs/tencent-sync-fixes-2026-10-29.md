# 腾讯房源同步修复记录

2026-10-30 更新：项目尚未上线，已删除历史版本适配与转换脚本。当前 Schema 初始化和数据格式以 [数据库初始化与结构维护](schema-setup.md) 为准；本文中的测试结果记录修复当时状态，外部阻碍仍未解除。

## 已落地代码

- 广东城市—地区映射，区县、东莞和中山镇街、常用功能区别名；未知地区、跨市区域、未知类型/业态显式报错。原始空间类型与泛零售描述单独保留。
- 腾讯来源房源业务字段由文档管理；集合 hook 防止 API 覆盖，原生后台和快速编辑限制业务字段编辑。推荐、排序、运营备注和紧急停显仍由后台维护。
- 独立 `emergencyHidden` 约束公开列表、详情及父子房源；不修改原有来源状态。
- 暂停/已出租先将已有房源停止公开，再解析资料；已出租且完整的资料随后保存为已满。
- 删行只针对同源记录；明确读取无筛选的全部房源视图，拒绝重复 ID、分页缺失、总数不一致。两次完整扫描间隔至少 15 分钟才停显，记录和图片不物理删除。
- `tencentSync` JSON 字段持久化缺失确认；数据库 advisory lock 串行化同步，来源配置变更生成新基线版本。默认周期 30 分钟。
- 报告新增停租、首次缺失、删行停显、恢复计数。图片仍维持现有六图同步限制，本轮不扩到九图。

## 尚未应用到运行环境

本机配置指向 `localhost:5432/zhaoshang_tencent_demo_20261024`。备份尝试返回 ECONNREFUSED；Docker 引擎也不可用。因此未执行 Schema push，现有数据库没有被修改。**必须先完成迁移再运行新后台/同步进程**，否则公开查询引用新增字段会失败。

本机演示数据库启动后：

1. 停止旧同步进程，确认数据库目标与备份范围。
2. 执行 `node backend/scripts/backup-tencent-sync.mjs`。该脚本仅接受本机指定演示库，备份 public 表数据、列和枚举到忽略提交的 scratch/backups；这是逻辑数据快照，不替代生产环境的完整 pg_dump 备份。
3. 执行 `pnpm --dir backend schema:push`，按当前集合配置审查差异。当前模型已移除历史分类标记，不能继续按“仅新增字段”判断变更；不要接受非预期的数据删除或重命名。
4. 保持正常运行 `PAYLOAD_DB_PUSH=false`，重启后台；真实授权接通后先检查同步报告，再启用定时同步。

生产迁移应使用对应数据库完整备份；不可使用仅限定本机演示库的备份脚本。
