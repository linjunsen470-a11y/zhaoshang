# 数据库初始化与结构维护

项目尚未上线，只维护当前 Schema 与客户端契约，不提供历史版本升级脚本或旧字段转换。

咨询称呼为选填，手机号为必填；调整此结构后须显式更新目标数据库，正常运行继续保持自动推送关闭。

收藏使用独立的 `favorites` 集合，按微信 OpenID 与房源 ID 建立唯一约束，并为房源 ID 建立索引，供后续按房源统计当前收藏人数。取消收藏会删除对应记录，因此此集合反映当前收藏，不代表历史累计或浏览量。房源 ID 独立保存，房源下架或删除后可向收藏者显示不可用占位。此结构上线前必须在隔离库验证，并在目标数据库备份后显式执行 Schema 更新。

在有权限的数据库只读会话中，可按房源汇总当前收藏数，不必导出用户标识：

```sql
SELECT project_id, COUNT(*) AS favorite_count
FROM favorites
GROUP BY project_id
ORDER BY favorite_count DESC, project_id;
```

收藏只在用户取消时删除，不能据此推断收藏次数、浏览次数或历史趋势。离线变更在重试成功后生效；不同设备同时修改同一收藏时，最终状态取决于操作在服务器执行的先后。

当前小程序尚未上线，新的同步状态不会自动导入旧版仅存本机的演示收藏。若发现已有真实用户依赖旧收藏，先保全数据并另行确定迁移方案。

发布前还需在微信公众平台的《用户隐私保护指引》中同步说明收藏的云端保存、跨设备同步、房源热度统计及取消收藏方式；代码内隐私政策更新不能替代平台配置和真机验证。

收藏数据库测试使用 `pnpm --dir backend test:favorites:db`。必须先准备并推送结构到独立本机 `/favorites_isolated_test` 数据库，设置 `DATABASE_URI` 指向该数据库，并显式设置 `FAVORITES_TEST_CONFIRM_ISOLATED=true`；测试会创建并清理专用的项目、账号、媒体和收藏记录，绝不能指向业务库。

1. 准备独立 PostgreSQL 数据库，在 `backend/.env` 配置 `DATABASE_URI`。
2. 若目标数据库已有数据，先备份并确认目标；不要自动删除或重建现有库。
3. 执行 `pnpm --dir backend schema:push`，检查结构变更。需要演示数据时执行 `pnpm backend:seed`。
4. 日常启动和构建保持 `PAYLOAD_DB_PUSH=false`。

房源必须明确选择场景；腾讯来源必须填写“场景”“场所名称”“校区/位置”，不再从旧字段或商铺类型推断。房源列表 API 固定返回 `{ docs, page, totalDocs, totalPages, hasNextPage }`，不再返回旧数组格式。清理本机演示 Storage 后可由当前代码重新生成演示数据。
