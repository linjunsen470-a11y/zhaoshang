# 商业项目接入：迁移与发布说明

## 本轮交付

复用 `projects`、原详情 ID 和咨询 API，新增发布内容、场景、父项目、位置名称、结构化面积/月租、介绍和经营条件字段。首页、找铺、详情、咨询、分享素材及内部管理工作台已适配。未接入短信、商户台账或归因追踪。

## 数据迁移

脚本：`backend/scripts/migrate-commercial.sql`，执行器：`backend/scripts/migrate-commercial.mjs`。

1. 在维护窗口停止内容写入，确认目标环境，制作整个 PostgreSQL 数据库的外部备份，并验证备份可恢复。库内备份不能替代完整备份。
2. 把正式库备份恢复到独立测试库，先在那里演练迁移及应用启动，核对记录数量、ID、咨询快照、收藏和历史分享路径。
3. 默认命令只输出 SQL；审阅后在目标后端环境执行带 `--apply` 的命令。不要在未确认目标库时执行。

```powershell
cd backend
pnpm migrate:commercial
pnpm migrate:commercial --apply
```

执行器使用环境变量 `DATABASE_URI`（缺省从 `backend/.env` 读取），不输出连接口令。迁移使用事务、咨询和项目表的首次库内备份、幂等列/索引创建及迁移锁。

### 迁移语义

- 旧记录原 ID 不变，统一补为具体铺位 `unit`。
- 明确校园旧类型映射为 `campus`；“其他”“店铺转让”等保持场景为空，标记 `legacyUnclassified`。仅历史记录享有待分类上架兼容，新记录不得借此绕过场景要求。
- 不从 `feeText`、`areaText` 提取数字。新增数值由运营核实后补录。
- 关联咨询的工作字段可按所属项目补充场景；`customerSnapshot` 不回写、不覆盖。
- 库内 `commercial_backup.projects_20260922` 和 `leads_20260922` 仅首次建立，重跑不会替换备份；它们不包含所有关系表，不能单独作为全库恢复来源。
- 新增广州区域及经营品类枚举，旧值保持不变。

不要先用 `PAYLOAD_DB_PUSH=true` 自动推送替代这次迁移：自动填充默认值可能使旧记录失去首次回填识别条件。先完成显式迁移，再启动新版应用。生产保持受控迁移方式。

### 发布与回滚

按「外部备份→测试库演练→目标库迁移→后端构建/发布→API 冒烟→小程序体验版→微信工具验收→正式发布」执行。上线前配置真实 HTTPS API、生产微信登录及真实项目内容，关闭演示模式。本次任务未改微信平台登记名称，也未执行正式库迁移或正式发布。

应用回滚时先暂停新内容录入，下架本轮新增商业项目及关联铺位，评估旧小程序不支持场景的展示影响。优先保留增量列与数据，仅回滚应用。需要数据库整体回退时，先另存上线后的新增/修改记录，再通过外部完整备份恢复；不直接删列，不用库内两张快照表覆盖线上数据库。

## API 约定

```text
GET /api/projects?pagination=true&page=1&limit=20
  &businessScene=community&listingKind=unit
  &area=50to100&rent=5000to10000
GET /api/projects?pagination=true&parentProject=123&page=1&limit=20
GET /api/projects?pagination=true&recommended=true&limit=6
GET /api/projects?pagination=true&sort=latest&limit=4
GET /api/projects/123
```

分页响应：`{ docs, page, totalDocs, totalPages, hasNextPage }`。不请求显式分页时仍返回数组（每页最多 100 条，兼容原接口）；新客户端一律请求显式分页。搜索、可见性、区间与关系筛选先在数据库执行，再分页。子铺位单独分页读取。

场景值 `campus/community/tourism/mall`；内容值 `project/unit`。面积值 `under50/50to100/100to200/200plus`；月租值 `under5000/5000to10000/10000to20000/20000to50000/50000plus`。未选维度省略或传「全部」。收藏可以通过 `ids` 过滤；`budget` 不再参与租金查询。

共享选项源是 `backend/collections/shared/commercialOptions.json`。更新后运行 `pnpm --dir backend sync:commercial-options` 生成微信端 JS，并运行根目录 `pnpm test:unit` 检查一致性。PostgreSQL 枚举新增另行准备增量迁移，不能只修改前端选项。

## 测试环境复现

本次使用独立库 `zhaoshang_commercial_test_20260922`，从原库仅复制 schema，未复制业务数据。`backend/tests/with-commercial-db.mjs` 仅为该本机隔离库的运行器，使用 `.env` 中凭据、固定本机数据库名和 3100 图片地址并禁用 schema push；不能作为生产启动命令。

```powershell
pnpm test:unit
pnpm --dir backend test:api
pnpm --dir backend test:cms
pnpm backend:lint
cd backend
node tests/with-commercial-db.mjs scripts/migrate-commercial.mjs --apply
pnpm test:commercial:db
pnpm test:commercial:migration
node tests/with-commercial-db.mjs node_modules/next/dist/bin/next dev --port 3100
# 在另一个终端、确认 3100 使用上述隔离库后：
$env:COMMERCIAL_TEST_CONFIRM_ISOLATED='true'
pnpm test:commercial:http
# 停止该测试服务后构建：
node tests/with-commercial-db.mjs node_modules/next/dist/bin/next build
```

数据库集成测试只允许指定隔离库，创建四类场景及超过 100 条测试记录。HTTP 测试仅访问本机 3100，测试咨询在测试结束时删除。迁移回归会在该隔离库制造历史记录，禁止在业务库运行。

微信本地 Mock 首次初始化包含校园、无子铺位项目、社区项目及两个子铺位、独立铺位和面议月租样例。已有本地缓存不会被覆盖；需要全套演示样例时，仅在开发者工具的测试项目中清除 `local_projects` 再重启。根目录 `server.js` 的轻量 Mock 同步了筛选与分页，但不是生产鉴权后端。

## 微信开发者工具回归命令

先登录微信开发者工具，并使用上述隔离后端。可以让测试自动启动工具，或连接已经开启的 9420 自动化端口：

```powershell
$env:MP_E2E_API_URL='http://127.0.0.1:3100/api'
$env:MP_E2E_MODE='connect'
pnpm test:mp:full
pnpm test:mp:commercial
```

专项脚本会暂时切换本地 Mock 并备份/恢复 `local_projects`、`local_leads`；仅在开发验收会话运行。微信专项仍有本地路由超时未全通过，详见验收记录。实际 PNG 上传、附件所有权以及咨询保存由 HTTP 测试验证，系统选图弹窗仍待交互走查。测试结果保存在 `test-results/mp-e2e`（不提交业务数据或口令）。
